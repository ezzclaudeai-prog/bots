1) الفكرة ببساطة: ما هو «الأوراكل»؟

الأوراكل = مقبس WebSocket ثانٍ متصل بخادم سريع (events-po.com) يصل سعره قبل مقبس التنفيذ (الديمو). الفكرة الأصلية: نستغل هذا «السبق» لتنفيذ صفقة في اتجاه الحركة قبل أن يعكسها فيد الديمو.

الحالة الفعلية في كودك: الأوراكل مُستخدَم كـ فلتر تأكيد (Veto) — يصوّت بنعم/لا على إشارة نمط الشموع — وليس كمولّد صفقات. (تفصيل في صفحة 2).

3) كيف «يقرأ» الكود سعر الأوراكل — خطوة بخطوة

1 توسيم المقبس: أي اتصال إلى events-po يُعلَّم أوراكل.
// سطر 784 if (urlStr.includes('events-po')) ws._dualRole = 'oracle'; if (_isTradeSocket(urlStr)) ws._dualRole = 'executor';
2 التقاط السعر من حدث signals (الحقل الثالث = السعر):
// سطر 1219-1229 if (evName==='signals') { const price = data[2]; // 2.03384 ← السعر الحي if (price > 0 && wsRef._dualRole==='oracle') DualWSSManager.recordOracleTick(asset, price); }
3 التخزين في مخزن مستقل (لا يختلط بتيكات الديمو):
// سطر 3989 function recordOracleTick(asset, price) { buf.push({ p: price, t: Date.now() }); // آخر 2.5ث فقط }
4 المنطق: هل ميل الأوراكل يوافق اتجاه الإشارة؟
// سطر 4003 function oracleAgrees(direction, asset) { if (تيكات < 3) return {agree:true}; // لا بيانات → اسمح (fail-open) slope = آخر سعر − أول سعر; // ميل الأوراكل if (|slope| < ضجيج) return {agree:true}; // مسطّح → اسمح oracleDir = slope>0 ? 'BUY' : 'SELL'; return {agree: oracleDir === direction}; // يطابق؟ }
5 البوابة: لو عارض الأوراكل → 🔮 [ORACLE-VETO] رفض. وإلا → تنفيذ على الديمو فقط (سطر 4742).

6) ⚠️ الاكتشاف الحاسم من سجلاتك

في كل سجلاتك لم يظهر 🔮 [ORACLE-VETO] ولا مرة واحدة. المعنى: المخزن _oracleTicks بقي فارغاً → أي أن events-po لم يبثّ أسعاراً لأزواجك (BHDCNY/CADCHF/AEDCNY) في جلساتك.

النتيجة: الفلتر مُطبّق وصحيح برمجياً، لكنه عملياً خامل (fail-open دائماً) لأن الأوراكل لا يغذّيه ببيانات. هذه هي الحلقة المفقودة بينك وبين المراجحة الحقيقية.
